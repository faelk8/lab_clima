# Post 2/5 — API confiável não basta

Fase vinculada: Fase 2. Status: RASCUNHO. Capa: “Uma resposta HTTP 200 não prova qualidade”. Artefato: gráfico comparando horas esperadas/recebidas e fluxo de retry. Evidência: `docs/evidence/F2-06.md` e relatórios de teste F2-02/F2-05.

No backfill do ClimateWatch, consultei 30 dias para três localidades brasileiras. O fluxo dividiu o intervalo em cinco janelas por cidade, preservou as respostas originais e registrou hashes e parâmetros no manifesto.

A execução recebeu 720 horas por cidade, sem lacunas nesse intervalo. Uma segunda execução reutilizou os 15 lotes concluídos sem novas chamadas. Também testei 429 com Retry-After, 5xx, timeout e respostas incompatíveis: erros temporários têm retry limitado; dados inválidos ficam preservados em quarentena.

Esses números descrevem uma janela de dados de modelo, não medições de estação nem uma tendência climática. O projeto continua exploratório e não emite alertas oficiais.
